## 🛠️ Процесс разработки

1. **Ветвление (Fork & Branch)**
   - Сделайте форк репозитория и создайте ветку от `canary` или `main`.
   - Используйте понятные названия веток: `feature/new-feature`, `fix/issue-123`, `refactor/audio-player`.

2. **Настройка локального окружения**
   - Используйте JDK 17 или JDK 21.
   - Скопируйте шаблон конфигурации Firebase:
     ```bash
     cp app/google-services.json.example app/google-services.json
     ```

3. **Стандарты кода и архитектурные правила**
   - **100% Jetpack Compose**: Никаких XML-разметок или Fragments.
   - **Префикс Vl**: Все переиспользуемые UI-компоненты библиотеки `ui/components/` именуются с префиксом `Vl` (`VlButton`, `VlCard`, `VlTextField` и др.).
   - **Языковые соглашения**:
     - Идентификаторы классов, функций, переменных и теги логов — строго на **английском языке**.
     - Комментарии в коде и коммит-сообщения пишутся на **русском языке**.
     - Тексты интерфейса добавляются синхронно в `res/values/strings.xml` и `res/values-ru/strings.xml`.
   - **Архитектура**:
     - MVVM / Unidirectional Data Flow (UDF).
     - Мутабельное состояние строго инкапсулировано через `StateFlow` (`private val _uiState` / `val uiState`).
     - Подписка в Compose только через lifecycle-aware вызовы: `collectAsStateWithLifecycle()`.
     - Все зависимости регистрируются в `di/AppModule.kt` через **Koin** (`single`, `viewModel`).
   - **Ограничение на новые библиотеки**: Запрещено добавлять тяжелые сторонние зависимости без предварительного обсуждения с мейнтейнерами.

4. **Тестирование и проверка**
   - Перед созданием Pull Request обязательно запустите юнит-тесты:
     ```bash
     ./gradlew testDebugUnitTest
     ```
   - Убедитесь, что сборка проекта проходит успешно:
     ```bash
     ./gradlew assembleDebug
     ```

5. **Создание Pull Request**
   - Опишите суть изменений, прикрепите скриншоты (при изменении UI) и укажите номер связанного Issue (например, `Fixes #12`).
