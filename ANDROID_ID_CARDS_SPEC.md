# VisorLink Android — ID-карты, режимы Protogen / Beast, тема Forge, Mask Mode

Спецификация для Android-клиента (**Kotlin**, **Jetpack Compose**, **Firebase Android SDK**) по функциям,
сделанным в вебе в ветке `id-cards` (план — `TODO.md` §11). Сервер и правила уже в `main`; Android должен
только читать данные, вызывать callables и повторять поведение интерфейса. **Писать в `idCards`,
`users.idMode` и `chats.groupId` напрямую нельзя** — это делают только Cloud Functions (правила запрещают).

Источники истины в вебе (при сомнениях — смотреть код):

| Что | Файл |
|---|---|
| Логика сервера (признаки, серийник, кулдауны, цены) | `functions/idCardLogic.js` |
| Callables | `functions/handlers/idCards.js` |
| Правила видимости | `firestore.rules` (блок «ID-КАРТЫ») |
| Клиентская модель (seed → детали, MRZ, штрихкод, подпись) | `src/utils/idCardModel.js` |
| Палитры карты, текстуры, маски голограмм | `src/components/idcard/cardStyle.js` |
| Графика карты (гильош, дорожки, окрас, LED-визор, штампы) | `src/components/idcard/cardArt.jsx` |
| Правила темы (чистые функции + тесты) | `src/utils/modeTheme.js`, `functions/test/modeTheme.test.js` |
| Токены темы Forge | `src/styles/variables.css` (блок FORGE v2) |

## 1. Включение

- **Android: флага больше нет** — ID-карты всегда включены для вошедшего пользователя, тема решается режимом.
- Исходно всё было скрыто за флагом Remote Config **`id_cards_enabled`** (по умолчанию `false`): при
  выключенном флаге не было выдачи карты, вкладки «ID-карта», тема всегда Biolume, карты в профилях не показывались.

## 2. Модель данных (читать; писать — только сервер)

### 2.1. `idCards/{uid}`
```jsonc
{
  "mode": "standard" | "protogen" | "beast",
  "species": "Snow leopard" | null,      // только для protogen/beast; у protogen подпись поля — «Модель»
  "serial": "VL-7KQM-3XPA",              // алфавит без похожих символов: ABCDEFGHJKMNPQRSTUVWXYZ23456789
  "traits": {
    "seed": 123456789,                   // uint32 — из него клиент выводит все мелкие детали (§4)
    "finish": "base" | "pearl" | "metallic" | "obsidian" | "gold",
    "laminated": true,
    "wear": 0 | 1 | 2 | 3,
    "foil": "none" | "classic" | "prism" | "aurora" | "galaxy",
    "variant": 0..11,                    // палитра
    "tilt": -1.5..1.5                    // наклон фото, градусы
  },
  "issuedAt": 1791200000000,             // мс
  "registeredAt": 1741910400000,         // дата регистрации аккаунта, мс (печатается на карте)
  "modeChangedAt": 1791200000000,
  "reissuedAt": null | 1791200000000,
  "version": 1                           // растёт при «Заменить документ»
}
```

**Тираж (edition)** не хранится — вычисляется из признаков (`editionOf` в `idCardLogic.js`):
очки `finish` (base 0, pearl 1, metallic 2, obsidian 3, gold 5) + очки `foil` (none/classic 0, prism 1,
aurora 2, galaxy 4); ≥ 7 legendary, ≥ 5 epic, ≥ 3 rare, ≥ 2 uncommon, иначе common.

### 2.2. `users/{uid}.idMode`
Только режим (`standard | protogen | beast`), без деталей карты. Читают все — нужен для темы чата и значка
режима. Отсутствует → считать `standard`.

### 2.3. `chats/{chatId}.groupId` (группы и каналы)
```jsonc
{ "enabled": true, "serial": "VL-…", "traits": { …как выше }, "issuedAt": 0, "changedAt": 0, "issuedBy": "uid" }
```

### 2.4. Правила видимости (проверяет Firestore, не только UI)
- Свою карту владелец читает всегда.
- Чужую — **только если у читающего самого `idCards/{me}.mode` ∈ {protogen, beast}**. Иначе
  `PERMISSION_DENIED` — это нормальный случай: просто не показывать блок карты, без ошибок в UI.
- `list` запрещён; запись — только сервер.

## 3. Callables (регион `europe-west1`)

Все требуют подтверждённый email (как остальные функции). Ошибки — `FirebaseFunctionsException`;
в `details` приходит `{ reason, waitMs? }`.

| Функция | Вход | Выход | Ошибки |
|---|---|---|---|
| `issueIdCard` | `{ mode, species? }` | `{ card, created }` | `invalid-argument` (режим/вид). Идемпотентна: если карта есть — вернёт её, `created: false` |
| `setIdMode` | `{ mode, species? }` | `{ card }` | `resource-exhausted` + `reason: "cooldown"`, `waitMs` (не чаще раза в **15 с**); `failed-precondition` + `reason: "no-card"` |
| `reissueIdCard` | `{}` | `{ card }` | `resource-exhausted` + `cooldown` (раз в **7 дней** от `reissuedAt`, а если его нет — от `issuedAt`); `failed-precondition` + `reason: "not-enough-bits"` (стоит **100 Bits**) |
| `setGroupIdCard` | `{ chatId, enabled }` | `{ groupId }` | только **владелец**; `permission-denied` + `reason: "standard-id"` если у владельца Standard; только `group`/`channel`; кулдаун 15 с |

`species`: до 40 символов, буквы любых алфавитов, цифры, пробел, дефис, апостроф; пусто → `null`.
Для `standard` сервер всегда обнуляет `species`.

## 4. Отрисовка карты

Карта — физический предмет 85.6 × 54 (соотношение), две стороны, псевдо-3D (поворот, переворот).
**Признаки решает сервер, мелкие детали — клиент из `traits.seed`**, детерминированно, чтобы карта
выглядела одинаково у всех и на всех платформах. Для этого портировать из `src/utils/idCardModel.js`
**один в один** (целочисленная арифметика, `>>> 0` → `toUInt()`/`and 0xFFFFFFFF`):

- `rng(seed)` — mulberry32;
- `deriveDetails(seed)` — `rng(seed xor 0xA11CE5)`; порядок вызовов `random()` важен: гильош, волны,
  форма и место голограммы, стиль/угол/нажим штампа, второй штамп, выражение LED-визора (0–7),
  окрас Beast (0–4), скол, отпечаток, пузырь плёнки, сдвиг печати, `artSeed`;
- `signaturePath(seed)`, `scratches(seed, n)`, `barcodeBars(serial)`, `mrzLines(…)` (с транслитерацией
  кириллицы).

Палитры (`cardPalette(mode, variant, finish)`), координаты графики (`viewBox 856×540`), эмблемы и штампы —
в `cardStyle.js` / `cardArt.jsx`. Допустимо упростить (например, без текстуры краски), но **цвета,
расположение полей и тексты должны совпадать**.

Состав сторон:
- **Лицо**: шапка (VISORLINK, «ID-карта» / у Protogen «// Реестр юнитов», значок режима), фото, поля
  (имя, ник, вид/модель, «В VisorLink с» = `registeredAt`, «Выдана» = `issuedAt`; у Protogen ещё серийник),
  штамп с датой регистрации, голограмма (если `foil != none`), наклейка из эмодзи профиля (до 2 символов).
  Standard — гильош, микротекст, подпись, «призрачное» фото. Protogen — срезанные углы, HUD-рамка,
  печатные дорожки, LED-визор с выражением. Beast — окрас, арочная рамка фото.
- **Оборот**: полоса, штрихкод, примечание, полоса подписи (у Protogen — «ключ подлинности»), блок
  «Тираж» (название + отделка · фольга), иногда второй штамп «Проверено», MRZ из трёх строк.

Анимация: наклон за пальцем, перетаскивание с инерцией, тап — переворот, **гироскоп** (наклон
относительно того, как держат телефон; база медленно подстраивается). Блик/радуга голограммы двигаются
от угла. Уважать «уменьшение движения» системы.

## 4a. Где карта в профиле

`users/{uid}.customization.idCardPosition`: `top` (над шапкой профиля) | `afterHeader` (под именем, по
умолчанию) | `bottom` (перед кнопками действий). Выбирается в «Кастомизации», **не PRO** — применяется у всех.
При сохранении кастомизации с Android **не терять** это поле (объект `customization` перезаписывается целиком).

Голограмма на лице карты — **всегда в правом нижнем углу**, никогда поверх фото. `deriveDetails().holoSpot`:
`corner` или `corner-tilt` (тот же угол, повёрнуто на −9°, чуть сдвинуто). Старое значение `photo` больше не
выдаётся (тот же вызов генератора, порядок не менялся — уже выданные карты не изменились, кроме места голограммы).

## 5. Выдача (первый вход и все существующие пользователи без карты)

1. Нет `idCards/{me}` → полноэкранная выдача, в приложение без карты не пускать.
2. Главный экран — **только Standard** и кнопка «Получить карту». Protogen / Beast **не показывать**:
   ни названий, ни превью.
3. Неприметная ссылка «Другой тип карты» → нейтральный экран («Режимы для фурри-сообщества…») с
   кнопкой «Показать» → только тогда выбор Protogen / Beast с превью и полем вида (необязательно).
4. `issueIdCard` вызывается **до** анимации; анимация показывает реальные признаки и серийник.
5. Церемония ≈ 6 с, можно пропустить: принтер, узор прорисовывается, фото проявляется, поля
   печатаются, штамп, ламинатор (если `laminated`), голограмма вспыхивает → «Карта выдана» → «Готово».
6. Подписка на `idCards/{me}` может прислать карту посреди анимации — экран не закрывать до «Готово».

## 6. Настройки «ID-карта» (видна при включённом флаге)

- Своя карта (можно вертеть).
- Режим: Standard всегда виден; Protogen/Beast — за кнопкой «Показать особые режимы», пока не выбраны.
  Смена — `setIdMode`, после неё отсчёт 15 с (кнопки других режимов неактивны).
- Вид/модель + «Сохранить» (тот же `setIdMode` с текущим режимом).
- **Маска** (§8) — только при особом режиме.
- «Заменить документ»: описание, цена 100 Bits, подтверждение, таймер до следующей замены; без
  Bits — кнопка неактивна с подсказкой.
- Настройки группы/канала: переключатель «ID группы» — **только владельцу с особым режимом**
  (остальным блок не показывать вовсе); при включении — карта группы.

## 7. Тема: Biolume / Forge

**Пользователь стиль не выбирает.** Выбор Biolume/Forge/Material из настроек и кастомизации убран
(поле `customization.style` в профиле не трогать — просто не читать).

Правила (`src/utils/modeTheme.js`, покрыты тестами — портировать как чистые функции):

```
special  = flag && idMode in {protogen, beast} && !masked
forge    = special && chatTheme != "neutral"
style    = forge ? "forge" : "biolume";  flavor = forge ? idMode : null
forceDark = special     // тёмная держится весь особый режим, даже в Biolume-чате
```

**Контекст чата** (`chatThemeFor`):
- ЛС: собеседник с особым режимом → `mode`; Standard → `neutral`; **бот → `mode` (боты тему не трогают)**;
  профиль собеседника ещё грузится → не менять тему (без мигания).
- Группа/канал: `groupId.enabled == true` → `mode`, иначе `neutral`.
- Вне чата (список чатов, настройки) → `mode`.
- Разные режимы в ЛС (Protogen ↔ Beast): каждый видит **свой** оттенок.

**Чужой профиль** (`ownerProfileThemeAttrs`): смотрящий с особым режимом видит панель профиля в гамме
**владельца** (его оттенок Forge, либо Biolume, если у владельца Standard). Остальные — в общей теме.

**Forge** — только тёмная, светлой версии нет; переключатель светлой темы при особом режиме неактивен с
подсказкой. Пресеты акцента — только в Biolume. Смена темы при входе/выходе из чата — плавная (~200 мс).

Ключевые токены Forge (полный список — блок FORGE v2 в `variables.css`):

| Токен | Protogen | Beast |
|---|---|---|
| background | `#06080C` | `#0B0907` |
| surface / container / high / highest | `#0A0E13` / `#10161E` / `#151D27` / `#1C2633` | `#110E0B` / `#1A1511` / `#221C16` / `#2B241D` |
| on-surface / variant | `#E2F4FA` / `#8DA3B3` | `#F4ECE2` / `#AE9F8E` |
| primary / on-primary | `#3DF2FF` / `#00191D` | `#FFB04D` / `#2A1600` |
| secondary | `#FF4FD8` | `#E7C27A` |
| error | `#FF4F6B` | `#FF6B5E` |
| скругления xs…2xl / full | 2–8 dp / 6 dp | 2–10 dp / 8 dp |

Структура Forge: плоские панели с 1 dp контуром цвета `primary` 16 % вместо неоморфных теней,
моноширинные заголовки разделов и метки (JetBrains Mono, капитель; у Protogen — префикс `> `),
у Protogen — едва заметные сканлайны на фоне. Значок Enterprise — в цвете `primary`.

**Android-слой поверх веба** (палитра, формы и контур те же; в вебе этого пока нет — переносить при желании).
Слой — свет, а не геометрия: срезанные углы, неоновые кромки у каждой панели, сетка фона и контуры пузырей
пробовали и отказались — слишком шумно.
- крупные заголовки (display, headline, titleLarge, в том числе верхняя панель) — **Unbounded** с мягким
  неоновым свечением основного цвета; текст кнопок — моно (JetBrains Mono);
- заголовки разделов — с линией до края, под верхней панелью — неоновая линия (основной → второй цвет);
- основная кнопка светится и в покое (опасная — нет);
- **PRO-акцент:** у владельца с активным PRO и выбранным акцентом (пресет или HEX) тема слегка
  подстраивается под него — основной неон на полпути к акценту (контраст ≥ 4.5:1 сохраняется), фоны
  и панели с оттенком 3–6 %; вторичный цвет, ошибки и статусы — цвета режима. Пресет акцента из
  настроек (не PRO) на Forge по-прежнему не действует;
- тумблер — светящаяся «риска» (планка 8×22 dp) вместо круглого бегунка, включённый трек подсвечен
  контуром и заливкой `primary`;
- фон: неоновая дымка сверху (`primary` 5–6 %), у Protogen сканлайны 1,8 % как в вебе.

## 8. Mask Mode (только на устройстве)

- Скрывает собственный особый режим **локально**: Biolume везде, обычный выбор светлой/тёмной темы,
  ID-карты в профилях (своя и чужие) не показываются, чужие профили — без гаммы владельца, значки режима
  скрыты. На сервер ничего не пишется, другие ничего не замечают.
- Сроки: до выключения, 15 мин, 1 ч, 4 ч, до завтра 9:00, до выбранного времени (ближайшее в будущем).
- Хранить `until` (мс или `null` = бессрочно) в DataStore; по истечении — снять автоматически
  (и при запуске, если срок прошёл, пока приложение было закрыто).
- Доступ: раздел во вкладке «ID-карта» и быстрая кнопка-маска (в вебе — нижняя строка сайдбара;
  на Android — например, меню профиля/шапки). Пока маска включена — индикатор «Маска до 18:30» с
  кнопкой снять. Только при особом режиме.

## 9. Значок режима

Маленький глиф (визор у Protogen, лапа у Beast; у Standard нет) у имени собеседника в шапке ЛС и у имени
в профиле. Показывать **только смотрящему с особым режимом и без маски** (себе в своём профиле — тоже).
Цвет — второстепенный текст, ненавязчиво.

## 10. Не-фурри не видят фурри-контент

Standard-пользователь не должен встречать Protogen/Beast случайно: онбординг (§5), настройки (особые
режимы за кнопкой), чужие профили (карты скрыты правилами), группы с «ID группы» (у него Biolume),
значки режима (не показываются), маска и «ID группы» (не показываются). Общие формулировки —
нейтральные («особый режим», «ID-карта»).

## 11. Проверка

- Standard: никаких следов особых режимов, кроме ссылки «Другой тип карты» на выдаче и кнопки
  «Показать особые режимы» в настройках.
- Protogen/Beast: Forge своего оттенка вне чатов; ЛС со Standard → Biolume; чат с ботом — тема не меняется; ЛС с другим особым
  режимом → свой оттенок; группа с «ID группы» → Forge; без → Biolume.
- Чужая карта видна только при собственном особом режиме; при Standard — `PERMISSION_DENIED` без
  ошибки в UI.
- Кулдаун 15 с (смена режима), 7 дней + 100 Bits («Заменить документ»), сообщения об ошибках по `reason`.
- Маска: переживает перезапуск, снимается по таймеру.
- Детали карты из одного `seed` совпадают с вебом (сравнить скриншоты одной карты).
