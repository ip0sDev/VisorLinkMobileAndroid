# Biolume — дизайн-система (v2.1)

**Статус:** платформенно-независимый документ. Значения токенов выражены в нейтральных единицах и нотации; рецепты для конкретных стеков собраны в §9 «Реализация на платформах».
**Дизайн-база:** Material 3 Expressive / Material You — анатомия компонентов, роли токенов и шкала форм берутся из спецификации M3E буквально, не «по мотивам». M3E — источник проектных решений, а не зависимость от Android: цветовые роли и type scale переносимы на любую платформу.
**Надстройка:** два независимых слоя глубины (неоморфная структура + редкий сигнальный неон), парная типографика, два разных «физических режима» освещения по темам.

**Единицы.** Размеры указаны в базовых единицах без масштаба: Android — dp, веб — px при devicePixelRatio = 1, iOS — pt; численно они совпадают. Запись `x y blur color` описывает смещённую тень (смещения по X/Y, радиус размытия, цвет с уже вложенной альфой); приставка `inset` — вдавленный вариант той же тени.

### Что изменилось в v2.1
- Документ отвязан от платформы: моушн описан параметрически вместо веб-сниппета, Compose-код перенесён из тела гайда в платформенное приложение §9.
- Закреплены уточнения, найденные при реализации: роль `selectionFill` для видимого выбора, плоский (не inset) pill активного пункта навигации, бабблы чата без рельефа, зазор 6–8 ед. под мягкую тень, ограничение Space Grotesk по алфавиту.

### Что изменилось в v2
- Глубина разделена на **структуру** (неоморфизм, нейтральный, всегда) и **сигнал** (цветной glow, только для фокуса/выбора/live-состояний). Раньше свечение было почти везде — из-за этого весь интерфейс читался как крипто-дэшборд.
- Primary сдвинут из зоны «кислотный крипто-тил» (`#3CF2C5`, hue ~165°) в более синюю, спокойную зону (`#35C7E8`, hue ~193°) — глубоководная люминесценция физически чаще синяя, а не зелёная (синий свет проходит толщу воды дальше).
- Светлая тема стала заметно менее жёлтой: фон `#F6F1DC` → `#F2F0E9`.
- FAB больше не пульсирует в покое — пульс остаётся только у реальных live-индикаторов.
- Добавлена явная таблица соответствия токенов и компонентов ролям M3/M3E.

## 0. Идея в одном абзаце

Глубоководные организмы производят свет сами; приповерхностные воды освещены солнцем и в этом не нуждаются. Отсюда — не только неон, но и физика поверхностей:

- **Abyss (тёмная).** Основа интерфейса — не светящаяся, а **сколотая из тёмного материала**: мягкий неоморфный рельеф, тени от несуществующего верхнего света. Неон появляется точечно — как биолюминесценция появляется в темноте только когда организм сигналит.
- **Tidepool (светлая).** Тот же принцип неоморфного рельефа, но при дневном свете — рельеф читается мягче, неон почти не нужен, вместо него — более глубокие, насыщенные версии тех же оттенков.

---

## 1. Принципы

1. **Структура ≠ сигнал.** Форма и глубина поверхности задаются нейтральным неоморфным рельефом. Цвет и свечение включаются только когда элемент что-то *сообщает* (фокус, выбор, live-статус) — никогда как базовое состояние.
2. **Один сигнал за раз.** На экране одновременно активен максимум один цветной glow. Если светится всё — не светится ничего, и вдобавок это читается как казино/обменник.
3. **Два океана — разная физика света**, но одна физика материала: неоморфизм работает в обеих темах, меняется только контраст теней (в Tidepool — мягче, т.к. окружающий свет уже есть).
4. **Мы наследуем M3E, а не переизобретаем.** Формы, варианты кнопок/карточек/навигации, шкала типографики и роли токенов — заимствуются из реальной спецификации Material 3 Expressive; Biolume добавляет только палитру, две гарнитуры сверху и неоморфную трактовку elevation.
5. **Данные — моноширинным.** Числа, таймштампы, ID остаются визуально отделены от «авторского» текста.

## 2. Соответствие Material 3 / M3 Expressive

Это отвечает на прямой вопрос «берём ли мы формы из M3E»: да, буквально —

| В Biolume | Что это в терминах M3/M3E |
|---|---|
| `surface`, `surfaceContainerLow/…/Highest` | Ролевые имена 1:1 из M3 color roles (`surfaceContainerLowest → surfaceContainerHighest`) |
| Filled / Tonal / Outlined / Text кнопка | Ровно 4 из 5 стандартных M3-вариантов кнопок (5-й, Elevated, не используем — его функцию берёт на себя неоморфная тень) |
| Форма кнопок — stadium (полный пилюльный радиус) | Дефолтная форма кнопок в M3 с 2023 года, не наша придумка |
| Форма FAB — асимметричный скруглённый прямоугольник | Часть shape-библиотеки M3 Expressive (FAB и контейнеры иконок могут брать формы из расширенного набора, не только идеальный круг/квадрат) |
| Морфинг формы кнопки при нажатии (радиус чуть уменьшается) | Паттерн M3E: контейнеры "морфят" форму на interaction-состояниях |
| Карточка = hairline outline + мягкая тень вместо контура | Наша трактовка M3 **Elevated Card** (elevation через тень) поверх геометрии **Outlined Card** — гибрид двух официальных вариантов |
| Пилюльный индикатор под активной иконкой в нижней навигации | Ровно паттерн M3 Navigation Bar (active indicator pill в `secondaryContainer`/`primaryContainer`) |
| Шкала типографики (display/headline/title/body/label, те же кегли/интерлиньяж) | Официальная шкала M3 type scale — меняются только гарнитуры и трекинг, не размеры |
| `tertiary` роль | Третий цвет триады Material You (primary/secondary/tertiary), у нас — редко используемый «лунный» акцент |

## 4. Глубина: два независимых слоя

### 4.1 Слой структуры — неоморфизм (нейтральный, база для всего UI)

Вместо теней Material по умолчанию или голого hairline-контура из v1 — мягкий двойной свет/тень от одного невидимого источника сверху-слева. Работает в паре состояний:

| Состояние | Где | Тень (Abyss) | Тень (Tidepool) |
|---|---|---|---|
| **Raised** (по умолчанию) | Карточки, tonal/outlined-кнопки, чипы, иконки-кнопки, thumb тумблера | `6px 6px 14px rgba(0,0,0,.45), -5px -5px 12px rgba(255,255,255,.025)` | `6px 6px 14px rgba(0,0,0,.08), -5px -5px 12px rgba(255,255,255,.9)` |
| **Inset** (врезано) | Текстовые поля, трек тумблера, нажатая кнопка/выбранный чип | `inset 4px 4px 8px rgba(0,0,0,.45), inset -3px -3px 6px rgba(255,255,255,.03)` | `inset 4px 4px 8px rgba(0,0,0,.08), inset -3px -3px 6px rgba(255,255,255,.9)` |

Логика raised/inset: элементы, которые **на что-то нажимают** (кнопки, чипы, thumb) — приподняты. Элементы, **во что-то принимают** (поля ввода, трек тумблера) — врезаны. Это стандартный принцип soft UI, а не декоративный выбор.

### 4.2 Слой сигнала — биолюм (цветной, редко, поверх структуры)

Добавляется **поверх** неоморфной структуры только для состояний, требующих внимания:

| Состояние | Что происходит |
|---|---|
| Focus (текстовое поле) | + 1px контур `primary` + `glowPrimary`, inset-тень остаётся |
| Selected (чип, вкладка, nav-item) | Плоская заливка `*Container`, БЕЗ glow — выбор сигналится цветом и pill-формой, не свечением |
| Live/Active (онлайн-статус, запись, загрузка) | + анимация «биопульс» (см. §6) — единственный источник анимированного свечения в состоянии покоя интерфейса |
| Primary CTA hover/press | Кратковременный `glowPrimary` только на время взаимодействия, не постоянно |

**Важное отличие от v1:** FAB, filled-кнопка и nav-индикатор в состоянии покоя теперь **не светятся**. Свечение — это ответ на действие или признак «живого» состояния, а не константа.

**Роль `selectionFill`.** Полупрозрачные `*Container`-заливки (alpha .10–.14) на поверхности контейнера почти не читаются как выбор — выделение выглядит как его отсутствие. Для выделенных состояний (pill навигации, выбранный чип, активный сегмент) вводится отдельная **непрозрачная** роль: плотная смесь `surfaceContainer` + акцента, ≈20 % в Abyss и ≈14 % в Tidepool. Она заметно слабее filled-CTA, чтобы выбор не считывался как кнопка.

## 6. Движение

### 6.1 Биопульс

Правило ужесточено по сравнению с v1: анимация допустима **только** там, где элемент действительно сообщает live-состояние — статус-точка «онлайн», индикатор загрузки, запись. FAB, кнопки и карточки **не пульсируют** в состоянии покоя.

Параметры (платформо-нейтральные):

- период **2400 мс**, easing ease-in-out;
- фаза покоя (0 % / 100 %): glow радиусом 10 ед. с альфой .22, плюс ядро альфы .45 нулевого радиуса;
- пик (50 %): glow разрастается до 20 ед. с альфой .45, кольцо расходится на 5 ед. и гаснет до нулевой альфы;
- цвет — текущий сигнальный акцент (`glowPrimary` и производные).

При системном запрете анимации (`prefers-reduced-motion`, шкала анимаций ОС = 0) биопульс заменяется статичным glow той же интенсивности, что на пике, — live-состояние остаётся видимым без движения.

### 6.2 Нажатие и микровзаимодействия

- Рельеф сам сообщает нажатие: **Raised → Inset** (тень морфит направление внутрь), без масштабирования элемента.
- Форма кнопки при нажатии слегка морфится (stadium → радиус ≈34 % диаметра) — паттерн M3E, см. §2.
- Пружина по умолчанию: damping ratio 0.75, stiffness 400. Линейный резерв для сред без пружин: 220 мс.
- Ограничения reduce-motion распространяются на любые циклические анимации.

## 7. Компоненты (кратко, с учётом слоёв)

- **Filled-кнопка:** заливка `primary`, форма stadium, лёгкая обычная тень (не цветная) в покое, `glowPrimary` — только hover/press. При `:active` радиус слегка уменьшается (shape-morph, см. §2).
- **Tonal / Outlined-кнопка:** neumorphic-raised, без цвета в покое.
- **FAB:** асимметричная M3E-форма, neumorphic-raised + статичный слабый `glowPrimary` (единственное исключение «всегда чуть светится», т.к. это главное CTA экрана) — но **без пульса**.
- **Карточка:** neumorphic-raised + `outlineVariant` (гибрид Elevated/Outlined из M3, см. §2).
- **Текстовое поле:** neumorphic-inset в покое → + контур/glow `primary` при фокусе.
- **Чип:** neumorphic-raised в покое → neumorphic-inset + `*Container` заливка при выборе, без glow.
- **Нижняя навигация:** плавающий stadium-контейнер — neumorphic-raised + нейтральная грань `outlineVariant`; активный пункт — **плоская** заливка `selectionFill` за иконкой (не inset: на низком pill ≈30 ед. высотой вдавленность читается грязью), без glow. Индикатор — sibling иконки, не её родитель (масштабирование родителя незаметно уменьшает иконку).
- **Бабблы чата:** без рельефа вовсе — в тесных контейнерах мягкие тени соседей накладываются и читаются грязными полосами. «Свой» — плотная подмешанная заливка (`surfaceContainer` + primary ≈22 % Abyss / ≈14 % Tidepool), «чужой» — нейтральный `surfaceContainer`.
- **Зазор под рельеф:** вокруг raised-элемента держать ≥6–8 ед. воздуха — мягкая тень рисуется вне границ компонента и срезается плотным родителем; где воздуха нет (плотные списочные ряды) — только грань `outlineVariant` без тени.

## 8. Сетка, отступы, иконография, доступность

Без изменений от v1, в нейтральных терминах: базовая сетка с шагом 4 (значения 4·8·12·16·24·32·48); иконки — шрифтовой набор Material Symbols Rounded (opsz 24, wght 400, fill 0→1 на выборе; шрифт портируемый, замена допустима при сохранении рублено-скруглённого стиля); контраст текста ≥4.5:1 (WCAG AA) в обеих темах для всех пар «текст/фон»; минимальная цель касания 48×48 ед.; биопульс и прочие циклические анимации отключаются системной настройкой анимаций.

## 9. Реализация на платформах

Токены §3–§6 ложатся в тему любой платформы один в один; различается только техника отрисовки двух слоёв глубины.

### 9.1 Общая схема (любой стек)

1. Палитры §3 → штатные цветовые роли платформы (M3 `ColorScheme`, CSS custom properties, семантические цвета SwiftUI, переменные Figma).
2. Структура §4.1 → двойная смещённая тень: тёмная от источника снизу-справа, светлая контр-подсветка сверху-слева; inset — та же пара, направленная внутрь контура.
3. Сигнал §4.2 → несмещённый glow + 1px контур акцентом, поверх структуры и только в активных состояниях.
4. Типографика §5 → кегли/интерлиньяж из официальной M3 type scale, гарнитуры подключаются ресурсами платформы.
5. Все параметры структуры/сигнала оформляются токенами и читаются компонентами из темы. Компонент не знает, какая тема активна: экраны вызывают одни и те же компоненты с одинаковой подписью во всех стилях.
6. Модификаторы глубины — чистые функции над токенами (без доступа к глобальному состоянию): так их можно ставить в условные ветки композиции любой платформы.

### 9.2 Jetpack Compose (Android)

- Токены раздаются `CompositionLocal`'ом рядом с `MaterialTheme`; компоненты читают их через единый аксессор и никогда не принимают тему параметром.
- Мягкая тень произвольной формы — `Paint.setShadowLayer` внутри `drawBehind`: штатный `Modifier.shadow` не даёт управлять смещением и не умеет вторую (контр-)тень.
- Inset-теней из коробки нет — рисуются тем же `setShadowLayer` по обводке пути либо масками с `BlurMaskFilter`.
- Модификаторы глубины делают **не-composable** с явным параметром токенов — так их можно безопасно ставить в условные ветки модификаторных цепочек.
- Эталонная реализация в этом репозитории: `ui/theme/VlDepth.kt`, сборка токенов — `ui/theme/Theme.kt`.

### 9.3 Web / CSS

- Структура ложится на `box-shadow` напрямую — таблицы §4.1 уже записаны в CSS-нотации; inset — префиксом `inset`.
- Биопульс §6.1 в терминах CSS:

```css
@keyframes biopulse {
  0%, 100% { box-shadow: 0 0 0 0 rgba(ACCENT,.45), 0 0 10px 2px rgba(ACCENT,.22); }
  50%      { box-shadow: 0 0 0 5px rgba(ACCENT,0),  0 0 20px 5px rgba(ACCENT,.45); }
}
```

- Отключение анимаций — `@media (prefers-reduced-motion: reduce)`: биопульс заменяется статичным `box-shadow` пиковой интенсивности.

### 9.4 SwiftUI / iOS

- Raised: два последовательных `.shadow(color:radius:x:y:)` — светлая контр-подсветка первой, тёмная тень поверх.
- Inset нативного аналога не имеет: эмулируется двумя смещёнными копиями фигуры под маской (`.overlay` + `blendMode`) либо отрисовкой в `Canvas`/`GraphicsContext` c `Shadow`.
- Биопульс — `TimelineView`/`PhaseAnimator`, управляющие радиусом и альфой тех же shadow-слоёв; пауза по `UIAccessibility.isReduceMotionEnabled`.

> Если платформенная техника не воспроизводит точный параметр (нет inset-теней, нет второго источника света) — допускается визуальное приближение, но не подмена смысла: inset обязан читаться вдавленностью, сигнал — свечением, а не обводкой.

## 10. Do / Don't (v2)

**Делать:**
- Структуру — неоморфизмом, сигнал — цветом. Никогда не смешивать роли.
- Максимум один цветной glow на экране одновременно.
- FAB — единственный элемент с постоянным (но статичным, без пульса) свечением.
- В Tidepool — глубину цвета и неоморфный рельеф вместо неона.
- Давать raised-элементам 6–8 ед. воздуха со всех сторон; в тесных контейнерах — нейтральная грань `outlineVariant` вместо тени.

**Не делать:**
- Не подсвечивать glow-ом состояние покоя (только hover/focus/press/live).
- Не использовать кислотно-зелёный/лаймовый в большой площади — читается как «прибыль» из трейдинг-интерфейса.
- Не путать outlineVariant (нейтральная грань) с сигнальным контуром (`primary`/`secondary`/`tertiary`) — это разные по смыслу токены.
- Не делать неоморфную тень на дефолтном фоне чистого `#000000`/`#FFFFFF` — рельеф не прочитается без разницы тонов.
- Не выдавать `primaryContainer` (полупрозрачный, alpha .10–.14) за индикацию выбора — для этого существует плотная непрозрачная `selectionFill`.
