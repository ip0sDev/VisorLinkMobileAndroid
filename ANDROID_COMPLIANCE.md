# Требования к Android-клиенту VisorLink для комплаенса и регуляторного соответствия
**Юрисдикция:** Закон Республики Беларусь от 07.05.2021 № 99-З «О защите персональных данных», ГК РБ, Google Play Developer Program Policies (Families, Data Safety, User-Generated Content).  
**Сервис / Домен:** VisorLink (`https://visorlink.org`)  
**Дата актуализации:** Сентябрь 2026 г.

---

## 1. Архитектурный обзор комплаенса
Android-клиент является критической точкой сбора данных, взаимодействия с датчиками устройства (камера, микрофон, память) и отправки сетевых запросов. Для обеспечения полной юридической чистоты и успешного прохождения аудитов/модерации в Google Play и национальных регуляторах клиент обязан соблюдать следующие разделы.

```
+-------------------------------------------------------------------------+
|                          Android Client Compliance                      |
+-------------------+--------------------+--------------------------------+
|  1. Consent & Age |  2. Google Play    |  3. Data Storage & Cryptography|
|  - 14+ Age Gate   |  - Data Safety Form|  - Android Keystore (E2EE)     |
|  - Cloud Function |  - Permissions Rationale - No plaintext message cache |
|    Audit Logging  |  - Account & Data  |  - Scoped Storage / MediaPicker|
|  - Active Re-check|    Deletion in-app |                                |
+-------------------+--------------------+--------------------------------+
|  4. UGC & Moderation                   |  5. Network & System Security  |
|  - In-app Report & Block               |  - TLS 1.3 / Certificate Pinning|
|  - Strict Channel Discovery Isolation  |  - FLAG_SECURE for sensitive UI|
|  - Moderation Status Badges            |  - Safe Push Notifications     |
+----------------------------------------+--------------------------------+
```

## 2. Юридические согласия, возрастной ценз и фиксация аудита (Закон № 99-З)

### 2.1. Блокирующий экран согласий (Legal Consent Gate)
1. **Момент показа:**
   - Сразу после первичного входа / регистрации (до отображения чатов и загрузки контактов).
   - Принудительно при обновлении версии юридических документов (`remote.acceptedVersion > local.acceptedVersion`). При этом доступ к интерфейсу блокируется до повторного подписания.
2. **Обязательные чекбоксы (явные действия субъекта данных):**
   - [x] Ознакомлен(а) и согласен(сна) с **Пользовательским соглашением (ToS)** (`legal_tos.json`).
   - [x] Ознакомлен(а) и согласен(сна) с **Политикой конфиденциальности** (`legal_privacy_policy.json`).
   - [x] Даю информированное согласие на обработку персональных данных в соответствии с **Политикой обработки ПД** (`legal_personal_data_policy.json`, ст. 5 Закона № 99-З).
   - [x] Подтверждаю согласие на трансграничную передачу данных на серверные мощности Google Cloud с пониманием сопутствующих рисков (ст. 9 Закона № 99-З).
   - [x] **Возрастной ценз:** «Мне исполнилось 14 лет (или получено письменное согласие законных представителей в порядке ст. 25 Гражданского кодекса Республики Беларусь)». Чекбокс должен быть явным (не предустановленным).

### 2.2. Серверная фиксация согласия (Cloud Function Audit Logging)
Клиент не должен просто локально ставить флаг в `SharedPreferences` или `DataStore`.
- **Действие:** Вызов Callable Cloud Function `recordUserLegalConsent`:
  ```json
  {
    "version": "1.2.0",
    "agreeTos": true,
    "agreePrivacy": true,
    "agreePersonalData": true,
    "agreeCrossBorder": true,
    "agreeAge14": true
  }
  ```
- **Что фиксирует сервер:** Точное время (`acceptedAt`), фактический IP-адрес клиента (`clientIp`), строку `User-Agent` (модель устройства, версия Android, сборка приложения).
- **Хранение в клиенте:** Токен/версия документа сохраняются в защищенном хранилище `EncryptedSharedPreferences`.

## 3. Требования Google Play: Data Safety, Permissions и удаление аккаунта

### 3.1. Политика удаления аккаунта и данных (Account Deletion Requirement)
Google Play требует, чтобы приложения с регистрацией предоставляли удаление аккаунта как внутри приложения, так и по веб-ссылке.
1. **Внутри Android-приложения:**
   - Путь в интерфейсе: `Настройки` -> `Конфиденциальность и безопасность` -> `Удалить аккаунт`.
   - Подтверждение через ввод пароля / биометрию или код подтверждения.
   - Очистка локальных ключей и базы данных: удаление локального SQLite/Room кэша, сброс мастер-ключей в Android Keystore, стирание токенов авторизации.
   - Запрос на сервер: вызов серверной функции каскадного удаления учетной записи и всех связанных сообщений/сессий.
2. **Веб-форма:** Ссылка на `https://visorlink.org/delete-account` должна быть доступна без обязательного скачивания приложения.

### 3.2. Доступ к разрешениям устройства (Runtime Permissions)
Android-приложение должно строго соблюдать принцип минимизации привилегий (Data Minimization):
1. **Камера (`CAMERA`):** Запрашивать исключительно во время нажатия пользователем на кнопку «Сделать снимок» или «Видеосообщение». Обязательно показывать предварительный системный диалог с пояснением цели.
2. **Микрофон (`RECORD_AUDIO`):** Запрашивать только в момент первой записи голосового сообщения или звонка. Запрещена фоновая запись.
3. **Хранилище / Фотографии (`READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`):** 
   - На Android 13+ (API 33+) обязательно использовать системный **Android Photo Picker** (`ActivityResultContracts.PickVisualMedia`), не требующий выдачи общего разрешения на все файлы устройства.
4. **Уведомления (`POST_NOTIFICATIONS`):** Запрашивать мягко через промежуточный экран (In-app Rationale), объясняющий, что уведомления требуются для доставки зашифрованных личных сообщений.
5. **Контакты (`READ_CONTACTS`):**
   - Если функция поиска контактов включена: хэшировать телефонные номера (SHA-256 с солью) **на стороне клиента** перед отправкой на сервер для мэтчинга. Запрещено передавать сырую адресную книгу.

## 4. Сквозное шифрование (E2EE) и локальное хранилище данных

### 4.1. Аппаратная защита ключей (Android Keystore)
1. **Генерация и хранение Identity Keys:** Приватные ключи пользователя (Identity Key, Signed Prekey, One-Time Prekeys) должны генерироваться с флагом `MasterKey` и храниться в аппаратном модуле **Android Keystore** (StrongBox Keymaster, если доступен на чипсете).
2. **Запрет бэкапа ключей в облако ОС:** В `AndroidManifest.xml` для личных данных и хранилища ключей должно быть жестко установлено:
   ```xml
   android:allowBackup="false"
   android:fullBackupContent="false"
   ```
   Или использовать правила исключения бэкапа для приватных баз данных и файлов ключей (`res/xml/backup_rules.xml`).

### 4.2. Шифрование базы данных сообщений (Encrypted SQLite)
1. Все сообщения и метаданные, кэшируемые локально для оффлайн-доступа, должны храниться в зашифрованной базе (например, **SQLCipher** / Room with SQLCipher) с 256-битным AES-ключом, защищенным Keystore.
2. Кэшированные медиафайлы (фотографии, голосовые) во внутреннем каталоге приложения (`context.noBackupFilesDir`) должны храниться в зашифрованном виде.

## 5. Модерация пользовательского контента (UGC) и изоляция каналов

В соответствии с требованиями регуляторов и правил Google Play (User-Generated Content Policy):
1. **Кнопка жалобы (In-app Report):**
   - Каждое сообщение в группе/канале, пост или профиль пользователя должны иметь действие: `Пожаловаться` (Report).
   - Категории: спам, насилие, оскорбления, незаконный контент, нарушение авторских прав.
   - Запрос уходит в `/reports` Firestore / Backend v2 с фиксацией ID контента.
2. **Блокировка пользователей (Block/Mute):**
   - Возможность заблокировать любого собеседника в 1 клик. Контент заблокированного пользователя немедленно скрывается из UI.
3. **Изоляция публичного контента (Channel Discovery):**
   - Отсутствие неконтролируемого поиска по произвольной подстроке среди публичных сообщений.
   - Отображение только верифицированных каналов из утвержденного реестра рекомендаций.
   - Для постов: отображение плашек статуса проверки (`is_published`, значок бота `unverified`/`official`/`visorlink`).

## 6. Защита интерфейса и предотвращение утечек данных

1. **Защита от скриншотов в секретных чатах (Screen Security):**
   - Для экранов секретных чатов / просмотра медиа с таймером самоуничтожения активировать системный флаг:
     ```kotlin
     window.setFlags(WindowManager.LayoutParams.FLAG_SECURE, WindowManager.LayoutParams.FLAG_SECURE)
     ```
   - Это предотвращает снятие скриншотов, запись экрана и утечку миниатюры окна в диспетчер недавних задач (Recent Apps / Overview screen).
2. **Маскировка текста в Push-уведомлениях (FCM Compliance):**
   - Для сквозного шифрования (E2EE): Push-уведомление через Firebase Cloud Messaging **не должно содержать открытый текст сообщения**.
   - По пейлоаду пуша клиент получает уведомление «Новое зашифрованное сообщение», поднимает локальный фоновый воркер, расшифровывает сообщение локальным ключом и формирует локальное системное `Notification`.
   - В логах Logcat запрещен вывод расшифрованного текста сообщений и приватных ключей (`BuildConfig.DEBUG` проверка).
